# App Demo Reel

Turns a web app into a polished 15–40s vertical demo video: real app screens, smooth GSAP motion, a fake cursor that taps through the flow, hook captions, a voiceover and a closing call to action. The output is a 1080x1920 H.264 MP4 at 60fps with AAC audio.

## 1. Brief (ask once, with AskUserQuestion)

- **App:** the URL, plus the source repo or connected folder if one exists. A repo gives the most faithful UI.
- **Flow:** which 3–4 moments to show (for example create, then add, then result). Each one becomes a scene.
- **Language(s) and tone:** any language, or several (one reel per language). For example English, Hindi, Hinglish, Bengali, Tamil, Telugu, Marathi, Gujarati, Kannada, Malayalam, Spanish, Arabic or Japanese. Playful or professional.
- **Audio:** one of
  - **Voiceover** (optionally with music under it),
  - **Music + captions only**, like the MyTripSplitter reel: no voice, the captions carry the story, with an instrumental bed,
  - **Silent** (the user adds trending audio in Instagram).
- **Voice** (if any): female or male, and the accent or region (for example en-IN, en-US, es-MX), or the user's own recording.
- **Music** (if any): the user's own track, or an original track generated by `scripts/music.py` in the mood they pick (upbeat, chill, corporate or cinematic).
- **Length:** the exact time frame the user wants (for example 7s, 15s, 30s, 60s, or the 15–90s Reels range). The final MP4 must be exactly that long.
- **Captions:** in the voice's language (default), in English, or both (bilingual: native line on top, English below).
- **Ending:** the call to action (URL or handle).

If the user is away, use defaults: Hinglish captions for Indian consumer apps, a female en-IN voice, 20s, and the URL as the call to action. If they ask for "just music" or "no voice", use music + captions with an upbeat generated track.

## 2. Get the real UI (best option first)

1. **Run the app from source.** Clone the repo (`gh repo clone ...`) or work in the connected folder. Run `npm i && npm run dev`, seed realistic demo data (Indian names and ₹ amounts if relevant), and open it with Playwright in the cloud workspace. These captures are pixel-true.
2. **Live site from the cloud workspace.** Use Playwright with `viewport {430x932}` and `deviceScaleFactor: 2.5` and take a screenshot of every state in the flow (before and after each tap). Use the app's own buttons and forms to get there. Never sign in with real credentials. Use a demo or test account the user provides, or a local/staging host.
3. **Cloud workspace egress blocks the site** (connect 403/DNS errors). Capture with the built-in browser on the user's computer instead (the screenshot tool, plus `javascript_tool` to read computed colours and fonts). To transfer images, return a base64 data URL from `javascript_tool`. For large strings, split them into 400-character chunks with a djb2 hash per chunk, verify locally, and re-fetch only the chunks that fail. Hand-copied base64 nearly always has an error or two.
4. **Fallback: rebuild.** Read the design tokens (`:root` CSS variables, fonts, gradients, logo) with `javascript_tool` and rebuild the screens as HTML that matches the brand exactly. Tell the user that this is a faithful recreation, not a capture.

Get fonts locally with `npm i @fontsource/<font>` and link their CSS files. Use Inter as the fallback so ₹ and other symbols always render. For emoji, use `font-family:'Noto Color Emoji'`.

## 3. Script and voiceover (the voice sets the timing)

Write one or two short lines per scene. Hook first (under 2s), then each step, then the call to action. Spoken lines can be longer than the captions.

### Writing in other languages

- Write natively in the target language rather than translating word for word. Keep it conversational, and keep brand names, the URL and on-screen UI labels exactly as they appear in the app.
- **Hinglish** (or Benglish, Tanglish and so on) stays in Roman script for captions. For the voice, give the TTS a version of the same line in a form it pronounces well (see the voice table).
- Have amounts and numbers spoken the local way, for example "48 hazaar 2 sau rupaye" in Hindi. If the TTS reads digits badly, spell them out in the spoken text, but keep digits in the captions.
- Caption length depends on the script: up to 24 characters per line at 72px for Latin and Devanagari, about 20 for Tamil, Malayalam and Telugu (their glyphs are wider), and about 12 for CJK. Check every hook in the preview stills.
- **Right-to-left** languages (Arabic, Urdu, Hebrew): set `dir="rtl"` on the caption container, reverse the word-stagger order, and mirror the cursor path only if the app UI itself is RTL.

### Fonts for captions

Install the matching Noto font with `npm i @fontsource/noto-sans-<script>`, add it to the caption `font-family` before Inter, and wait for it in `document.fonts.load()`:

| Script | Fontsource package |
|---|---|
| Devanagari (Hindi, Marathi, Nepali) | `noto-sans-devanagari` |
| Bengali, Assamese | `noto-sans-bengali` |
| Tamil / Telugu / Kannada / Malayalam | `noto-sans-tamil`, `-telugu`, `-kannada`, `-malayalam` |
| Gujarati / Gurmukhi (Punjabi) / Odia | `noto-sans-gujarati`, `-gurmukhi`, `-oriya` |
| Arabic / Urdu | `noto-sans-arabic` (Urdu: `noto-nastaliq-urdu`) |
| Japanese / Korean / Chinese | `noto-sans-jp`, `-kr`, `-sc` |
| Thai | `noto-sans-thai` |

Indic scripts need 1.25–1.35 line-height and extra bottom padding on `.ln`, or the matras get clipped.

### Generating the voice

Generate one audio file per scene, then read each file's length with `ffprobe -show_entries format=duration` and set the scene lengths from them, plus about 0.3s of breathing room. Try these voice options in order:

1. **edge-tts** (free neural voices in 100+ languages): `pip install edge-tts --break-system-packages`, then `edge-tts --voice <voice> --rate +8% --text "..." --write-media s1.mp3`. Run `edge-tts --list-voices | grep -i <locale>` to see every voice for a locale. Common picks (female / male):

   | Language | Voices |
   |---|---|
   | English (India) / Hinglish in Roman script | `en-IN-NeerjaNeural` / `en-IN-PrabhatNeural` |
   | Hindi (Devanagari text) | `hi-IN-SwaraNeural` / `hi-IN-MadhurNeural` |
   | Bengali | `bn-IN-TanishaaNeural` / `bn-IN-BashkarNeural` |
   | Tamil | `ta-IN-PallaviNeural` / `ta-IN-ValluvarNeural` |
   | Telugu | `te-IN-ShrutiNeural` / `te-IN-MohanNeural` |
   | Marathi | `mr-IN-AarohiNeural` / `mr-IN-ManoharNeural` |
   | Gujarati | `gu-IN-DhwaniNeural` / `gu-IN-NiranjanNeural` |
   | Kannada | `kn-IN-SapnaNeural` / `kn-IN-GaganNeural` |
   | Malayalam | `ml-IN-SobhanaNeural` / `ml-IN-MidhunNeural` |
   | Urdu | `ur-IN-GulNeural` / `ur-IN-SalmanNeural` |
   | English (US) / (UK) | `en-US-AvaNeural` / `en-US-AndrewNeural`, `en-GB-SoniaNeural` / `en-GB-RyanNeural` |
   | Spanish (Mexico) / (Spain) | `es-MX-DaliaNeural` / `es-MX-JorgeNeural`, `es-ES-ElviraNeural` / `es-ES-AlvaroNeural` |
   | Arabic (UAE) | `ar-AE-FatimaNeural` / `ar-AE-HamdanNeural` |
   | French / German | `fr-FR-DeniseNeural` / `fr-FR-HenriNeural`, `de-DE-KatjaNeural` / `de-DE-ConradNeural` |
   | Japanese | `ja-JP-NanamiNeural` / `ja-JP-KeitaNeural` |

   For Hinglish, the en-IN voices read Roman-script Hinglish naturally. For a more Hindi-sounding delivery, give `hi-IN-*` the same line written in Devanagari while the captions stay in Roman script. If the cloud workspace can't reach `speech.platform.bing.com`, run the same commands on the user's computer with device_bash, then stage the MP3s.
2. **ElevenLabs or OpenAI TTS**, only if the user supplies an API key. ElevenLabs `eleven_multilingual_v2` covers about 29 languages and handles code-mixed Hinglish best; use the same voice ID for every language version so the brand voice stays consistent. Never ask the user to paste a key into chat if an environment variable is available.
3. **The user's own recording** in any language. They attach it, and you cut it per scene with `ffmpeg -ss/-to`, or time the scenes to it with `ffmpeg -af silencedetect`.
4. **No voice.** Captions only; say so in the reply.

Before rendering, listen for mistakes in each clip: run it through a speech-to-text check if one is available, or at least compare its length against the expected speaking rate. Re-generate any clip with wrong pronunciation of the brand name. A phonetic spelling in the spoken text usually fixes it.

### Several languages at once

Keep all copy in one `LANG` object (`{ hi: { hooks, cta, vo: [...] }, en: {...} }`), choose it with `?lang=hi` in the stage URL, and render each language to its own file (`<app>_reel_hi.mp4`, `<app>_reel_en.mp4`). Scene timings come from that language's audio, so build the timeline after reading the clip lengths for the chosen language. Pass the lengths in with `?dur=2.4,3.1,...`.

For music, see 3c. If the user would rather use a trending track, deliver the reel without music and tell them to add it in the Instagram app.

## 3b. Fit the reel to the user's time frame

Plan the scenes from the target length before building anything. A rough budget:

| Length | Scenes | Shape |
|---|---|---|
| 6–10s | hook + 1 key moment + CTA | one tap, one payoff |
| 15s | hook + 2 moments + CTA | about 3s per moment |
| 20–30s | hook + 3 moments + CTA | the MyTripSplitter layout |
| 45–60s | hook + 4–6 moments + CTA | add a feature per scene, 7–9s each |
| 60–90s | as above, plus a problem/solution intro | keep each hook under 3s |

Leave the call to action on screen for at least 2s, and keep the hook under 2.5s whatever the length.

- **With a voice:** write to the length. Allow about 2.5 words per second for English and Hinglish, and about 2.2 for Hindi and the other Indian languages. Then nudge the speed with edge-tts `--rate` (stay within ±15%). Fill any gap with longer holds, not slower speech.
- **Captions only:** build the scenes for the target length directly, then render with `DUR=<seconds>`.
- **Small changes** (0.75–1.35× of the stage's natural length): render the same stage with `DUR=<seconds> node render.js`. It re-times the whole timeline uniformly and outputs exactly that many seconds.
- **Bigger changes:** add or drop scenes and lengthen or shorten the holds in the stage, then render. Don't speed everything up 2×; it looks frantic.

Always check the result with `ffprobe` against the requested length (±0.05s).

## 3c. Music

Never use copyrighted or "trending" tracks. There are two allowed sources:

1. **The user's own track** (one they made or have a licence for). Trim it to the length with `-ss`/`-t`, add a 1.2s fade-out (`afade=t=out:st=<len-1.2>:d=1.2`), and normalise it with `loudnorm=I=-14:TP=-1.5`.
2. **An original track generated with `scripts/music.py`:**
   `python3 music.py --dur <seconds> --mood upbeat|chill|corporate|cinematic [--bpm 112] [--key C] [--seed 1] --out music.wav`.
   It synthesises chords, bass, an arpeggio and drums (no samples), comes out at exactly `--dur` seconds with an intro bar and an outro fade, at about -14 LUFS. It prints the beat grid as JSON (`beat`, `bar`, `bars`). Change `--seed` or `--key` for variety, and match the mood to the brand (upbeat for consumer and travel apps, corporate for B2B, chill for lifestyle, cinematic for launches).

**Sync the motion to the music:** start scene changes and the CTA on bar starts from the beat grid, and put cursor taps on beats. Set the scene times from the `bars` array, or choose `--bpm` so a bar length matches your scene length. If you re-time with `DUR`, generate the music for the final `DUR` and recompute the grid.

**Mixing:**
- Music only: `ffmpeg -f concat -safe 0 -i list.txt -i music.wav -map 0:v -map 1:a -c:v copy -c:a aac -b:a 192k -shortest -movflags +faststart out.mp4`.
- Voice plus music: lower the music to about -20 dB under the voice and duck it on speech: `[1:a]volume=0.35[m];[m][vo]sidechaincompress=threshold=0.03:ratio=8:release=250[duck];[duck][vo]amix=inputs=2:normalize=0,loudnorm=I=-14:TP=-1.5`.

In music-only reels the captions must tell the whole story, so give each scene a clear two-line hook and keep each hook on screen for at least 1.6s.

## 4. Build the stage (`index.html`, 1080x1920)

The layout, kept inside the Reels safe zone: hook text at y≈180–440, the app screen or panel at y≈460–1420, a step indicator at about y 1460, and nothing important below y 1560 (the Instagram caption covers it) or right of x 960 below y 1000 (the Instagram buttons).

- **App screen:** a real screenshot set inside a rounded frame, or the rebuilt HTML. Animate between states with crossfades, slides and zoom/pan (`scale` 1→1.35 onto the tapped area, then back).
- **Cursor:** an SVG arrow with a ripple. A tap scales the cursor to 0.82 and back, expands the ripple, and scales the target to 0.94.
- **Motion ideas:** counters ticking up, progress bars, rows staggering in, an SVG path drawn with a stroke-dashoffset mask, and an icon flying along the path (`getPointAtLength` plus an `atan2` rotation).
- **Captions:** big Plus Jakarta / Inter 800 hook lines. Mark gradient words like `*word*` and animate them in per word (yPercent 115→0).

**Deterministic timeline (required).** Use one paused `gsap.timeline()` and no CSS animations, `setTimeout` or real-time video. Expose:

```js
const renderers=[]; // DOM writers for counters / path-following
const counter=(el,from,f)=>{const o={v:from};renderers.push(()=>el.textContent=f(o.v));return o;};
window.seek=t=>{tl.time(t,false);renderers.forEach(r=>r());};
window.DUR=TOTAL;
// after document.fonts.load(...) for each font: build(); seek(0); window.READY=true;
```

Measure the cursor targets with `getBoundingClientRect()` before applying any initial transforms. Use absolute positions for cursor moves, not relative ones. Set scene start times from the voiceover lengths in step 3.

Before the full render, preview stills: walk `seek()` forward to about 8 timestamps, screenshot each, tile them into a contact sheet, and Read it. Fix text overflow, overlaps and safe-zone problems.

## 5. Render

The cloud workspace has 2 CPUs, so use 2 workers. Each worker renders a frame range: `seek(f/60)`, then a JPEG screenshot at quality 95, piped into ffmpeg (`-f image2pipe -c:v mjpeg -i - -c:v libx264 -crf 16 -pix_fmt yuv420p -r 60 seg_N.mp4`). Warm-walk each worker from 0 to its start in 0.25s steps first. That renders about 6 fps per worker, so 20s takes about 2 minutes. Run it in the background with nohup and poll the log.

Audio and muxing:

```bash
# place each VO clip at its scene start (ms), mix, normalise
ffmpeg -i s1.mp3 -i s2.mp3 ... -filter_complex "[0]adelay=150|150[a0];[1]adelay=2700|2700[a1];...;[a0][a1]...amix=inputs=N:normalize=0,loudnorm=I=-14:TP=-1.5[vo]" -map "[vo]" vo.wav
# optional user-supplied music, ducked under VO
#   [music]volume=0.25[m];[m][vo]sidechaincompress=threshold=0.03:ratio=8[duck];[duck][vo]amix=2
printf "file 'seg_0.mp4'\nfile 'seg_1.mp4'\n" > list.txt
ffmpeg -f concat -safe 0 -i list.txt -i vo.wav -map 0:v -map 1:a -c:v copy -c:a aac -b:a 192k -shortest -movflags +faststart /mnt/user-data/outputs/<app>_demo_reel.mp4
```

If there is no voice, mux silent audio with `-f lavfi -i anullsrc=r=48000:cl=stereo`.

## 6. Verify, then deliver

- Use `ffprobe` to confirm the format: 1080x1920, 60/1 fps, h264 plus aac, and a duration within ±0.05s of the length the user asked for.
- Pull about 10 frames with `select='eq(n,..)'`, tile them, and Read the sheet. Also check the frames on either side of each worker seam (they should continue smoothly) and check the voiceover timing against the scene changes.
- Deliver each language's MP4 with SendUserFile. Reply in one or two sentences: what the reel shows, its length, which languages, voices and music were used, and (if it has no music) a reminder to add audio in the Instagram app.
- Offer to post through a connected Instagram/Zapier action only with explicit permission. Note that music can't be added through the API.

## Bundled files

- `scripts/stills.js`: `node stills.js 1.6,4.9,9.6 <outdir>` walks the timeline and saves preview PNGs.
- `scripts/render.js`: `W=2 [DUR=15] [QUERY=lang=hi] node render.js` renders `index.html` in the current folder into `seg_N.mp4` worker segments at 60fps, re-timed to `DUR` seconds if given.
- `scripts/music.py`: generates an original instrumental of an exact length and mood, and prints its beat grid.
- `examples/mytripsplitter/index.html`: a complete 19.7s stage (hook text, rebuilt app panel, cursor taps, counters, a path-following plane and a CTA) to copy as a starting template. It needs `npm i gsap @fontsource/plus-jakarta-sans @fontsource/manrope` in the same folder.

Copy the scripts and template into a working folder, then follow the steps above.
